---
title: Best Practices
description: Practical guidance for creating a story map that supports product and delivery decisions.
---

A useful story map makes the sequence of the user experience visible and helps a team choose a coherent slice of work. Treat it as a shared planning model, not as another place to duplicate every backlog item.

## Start with the conversation

Name the user, their goal, and the decision the team needs to make. Build only the part of the journey needed for that decision. A focused map is easier to review and maintain than a map that tries to represent every possible scenario.

## Make the backbone tell a story

Read the backbone from left to right. Each item should describe a recognizable step or capability. Keep backbone items at a comparable level of detail so the sequence remains understandable.

## Add detail deliberately

Place work beneath the step it supports and order important items first. Add enough detail to expose choices, dependencies, and gaps. Keep the full issue description and acceptance criteria in Jira.

## Slice for outcomes

Use horizontal sprint or release lanes to select an end-to-end result. A strong slice crosses the journey and provides a usable outcome. Avoid filling a lane only because the team has remaining capacity.

## Review the map as work changes

Revisit the backbone when the product direction changes. Review unassigned issues during planning, and remove obsolete map structure without deleting Jira issues that the team still needs.

For terminology and scope, see [Story Mapping vs. Journey Mapping](/docs/best-practices/storyvsjourneymap).
